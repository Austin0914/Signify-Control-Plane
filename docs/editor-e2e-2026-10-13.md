# First Unity Editor/dev integration walkthrough

The live Amplify operator console was exercised against the dev backend and Unity 6000.3.5f2 on 2026-10-13, with repairs verified through 2026-10-14 (Asia/Taipei). Core flows worked, and the walkthrough exposed command TTL, tracking, NACK correlation and device listing defects. This is partial Plan 09 evidence, not complete Plan 09 or Vision Pro acceptance.

## Verified behavior

- Independent device pairing, authenticated WebSocket readiness and real REST config loading.
- Two published fixtures loaded as `Remote`, with their actual session IDs, revisions, routes and word order: revision 2 used `landing → learn-word → ending`; revision 3 used six stages and reversed words. The second fixture's active first word was actually bound to 「開心」.
- Landing deferred navigation with `landing_locked`, then emitted an `activated` terminal result for the same command after normal Landing completion.
- Manual correct/wrong judgment emitted `manual_remote` results with the expected attempt identity. A rapid double-click produced one wrong command and kept the same active word index.
- Expected phase/epoch LearnWord advance, ending navigation and return to a new LearnWord instance.
- A forced socket disconnect produced a new connection identity while preserving the active section instance and generation.
- Device revocation disabled Web operations and prevented authenticated reconnect. A subsequent boot fell back to `PackagedDefault` with `http_error`, rather than loading remote config.

An opt-in Editor-only helper supplied synthetic floor/mesh inputs and a fixed head pose, disabled physical hand sampling, and called the existing `LandingInputBallController.TryTriggerPop()` entry. SceneFlow and judgment authority were unchanged. These results do not prove XR tracking or model accuracy.

## TTL defect and repair

The failed wrong command had `issuedAt` ending in `.509Z` and `expiresAt` ending in `.510Z`, making its lifetime **60.001 seconds**. Unity correctly rejected this envelope because its maximum TTL is 60 seconds. The cloud trace was replayed through the actual Unity parser and reproduced `invalid_payload`.

The operator API now computes expiration from its already captured issue time. The shared contract also enforces a positive TTL of at most 60 seconds. Regression coverage checks exact-boundary, one-millisecond overflow, zero and negative lifetimes. `npm run check` passed all typechecks, 12 tests and production builds.

The repair was deployed to `SignifyControlPlane-dev`; the reviewed CDK diff contained only Lambda code and asset metadata, and CloudFormation reached `UPDATE_COMPLETE`. A second paired walkthrough verified four live commands: navigation activated, wrong and correct judgments completed, and snapshot ingress accepted. Their cloud records all had an exact 60,000 ms TTL. The test device was revoked again and the original Editor settings restored afterward.

## Follow-up repairs

- The console now offers confirmed same-section restart using the existing `navigate_section` command. It checks the device and section instance again at confirmation so a changed stage is not restarted accidentally.
- Pending judgments are tracked independently from the most recent operation. Expired/rejected attempts can be retried after a snapshot request; completed attempts remain locked against stale snapshots, and late responses cannot unlock a newer retry.
- Parse-failure NACKs with sequence zero now resolve the existing command by ID. Unidentifiable and foreign-device commands cannot create or alter a command row; terminal statuses remain protected.
- Device listing now queries the device-key prefix and follows all DynamoDB pages. The previous filtered scan stopped after 100 mixed records and could hide connected devices. Regression coverage includes an empty filtered first page and credential redaction.
- Backend tests resolve shared-contract source directly, so fresh CI checkouts do not require generated contract output before running tests.

All typechecks, 21 tests and builds passed, including a clean-build check without pre-existing contract output. GitHub Actions passed for functional commit `e17c62a0aa716157e11ef090deecc545be870dda`; Amplify job 10 succeeded and the dev backend reached `UPDATE_COMPLETE`. A browser run using the real React component with a deterministic fake API verified double-click deduplication, expiry unlock after tracker replacement, stale-snapshot success locking, restart confirmation/cancellation, new-attempt readiness and rejection of confirmation after an external stage change. This mocked browser coverage is separate from the live checks below.

## Live repair verification and cleanup (2026-10-14)

The independently paired test device used the restored original course, `demo-session` revision 4. The Editor-only fault helper held command processing while continuing real five-second heartbeat traffic through the existing processor/outbound queue; it did not spoof authority results or replace protocol validation.

- A malformed envelope with a 60,001 ms TTL, injected for real command sequence 16, produced `command_nack` with sequence zero and `invalid_payload`. The backend correlated its command ID and marked the existing row `rejected`; Web judgment buttons recovered without reloading. An earlier attempt that stopped heartbeats only expired and is retained as failed harness evidence, not a passing NACK test.
- A real judgment (sequence 17) remained pending while a snapshot request (sequence 18) replaced the recent-operation tracker. After both deadlines passed, releasing ingress produced actual `expired_command` NACKs and rejected rows. The Web unlocked the original attempt without a reload; the connection identity and learning progress remained unchanged.
- Retrying correct judgment (sequence 19) produced `judged_correct`, `manual_remote`, and the expected original attempt ID. Unity advanced its active word index from 0 to 1 and created a new attempt.
- Cancelling same-section restart sent no command and preserved generation 2/index 1. Confirming it sent real `navigate_section` sequence 20 and received terminal `activated`: `learn-word@g2` became `learn-word@g3`, generation 3, word index 0, with a new attempt. ACK was not treated as completion.
- Device listing again showed both existing devices after the mixed-record population exceeded the former scan boundary.

After the entire round, the test device was revoked and Web operations became disabled. Play Mode stopped, the helper was disabled, and original settings, device ID and credential expiry matched the saved baseline. The credential slot was restored privately by the helper; no credential value was emitted. The original published course stayed at revision 4 and the draft was not changed during this repair round. Evidence includes `repair-restart-command.json`, `repair-restart-stable.json`, `repair-nack-result-healthy.json`, `repair-expiry-results.json`, `repair-unity-restoration-final.json` and the corresponding Web screenshots.
