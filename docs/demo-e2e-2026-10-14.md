## Defects found and repaired

- Ingress NACKs can now close `accepted`/`deferred` commands without overwriting completed terminal results.
- Unity terminal replay no longer adds a `serverSequence` field absent from the original result. Both terminal schemas are strict; the first lost-result run exposed this rejection. ACKs retain their sequence and replay marker, while terminal event identity is preserved.
- Already ACKed, unresolved commands are replayed after their admission deadline with the original envelope and unchanged expiry. The same runtime can return its cached result; a fresh runtime rejects expired or nonexistent work. Unacknowledged queued/sent commands still expire without new execution.
- Pending replay follows all DynamoDB pages, including completed-only pages preceding unresolved commands.
- Accepted snapshot requests remain complete with their ACK, because they have no terminal result. During repair an earlier snapshot test row (sequence 12) was rejected on reboot before this special case was added; that historical audit row is retained.

The original lost-result sequence 32 failed to complete after reconnect and is retained as failing evidence. Sequence 34 is the passing post-repair rerun. Broader lost-ACK-plus-result, model/manual race, server restart, Fatal, other malformed/oversize traffic, soak, canonical flow validation and Unity test discovery are still open.
